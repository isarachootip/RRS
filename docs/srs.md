# Software Requirements Specification (SRS)
# โปรแกรมบริหารงานเช่าคอนโด (Condo Rental Management System)

**Version:** 1.0
**วัตถุประสงค์:** เพื่อบริหารคอนโดที่เป็นทรัพย์สินของบริษัท/เราเอง และคอนโดที่รับฝากเช่าจากเจ้าของห้อง โดยมีฐานข้อมูลกลาง รองรับการทำงานหลายคน ติดตามการเช่า และคำนวณรายได้และค่าคอมมิชชันได้อย่างถูกต้อง

## 1. ภาพรวมระบบ (System Overview)

ระบบต้องรองรับการทำงาน 2 รูปแบบ

1. **Owner:** คอนโดที่เราเป็นเจ้าของเอง รายได้จากค่าเช่าเป็นของเรา
2. **Agent:** คอนโดที่รับฝากจากเจ้าของห้อง รายได้เป็นค่านายหน้าหรือค่าบริการตามข้อตกลง

ระบบต้องแยกประเภททรัพย์สินและรูปแบบรายได้ได้ แต่ใช้ฐานข้อมูลลูกค้าและระบบจัดการงานร่วมกัน

### 1.1 ประเภทผู้ใช้งาน

- **Admin:** จัดการระบบ ข้อมูลทั้งหมด ผู้ใช้งาน และสิทธิ์การเข้าถึง
- **Manager:** ดูแลทีม มอบหมายลูกค้า ติดตามยอดเช่าและผลการทำงาน
- **Agent:** ดูข้อมูลลูกค้า ทรัพย์สิน การนัดหมาย และงานที่ได้รับสิทธิ์
- **Accounting:** ตรวจสอบรายได้ ค่าคอมมิชชัน รายจ่าย และการจ่ายเงิน

ต้องกำหนดสิทธิ์แยกตามบทบาท โดย Admin สามารถกำหนดเพิ่มเติมได้

## 2. Module 1: ฐานข้อมูลลูกค้าและทรัพย์สินกลาง

### 2.1 ฐานข้อมูลเจ้าของห้อง (Owner Database)

จัดเก็บข้อมูลเจ้าของห้องที่นำคอนโดมาฝากเช่า ข้อมูลที่ต้องมี:

- Owner ID (รหัสเจ้าของห้องอัตโนมัติ)
- ชื่อ-นามสกุล
- เบอร์โทรศัพท์
- LINE ID
- อีเมล
- ช่องทางที่รู้จักเรา
- วันที่เริ่มติดต่อ
- Agent ผู้ดูแลเจ้าของห้อง
- หมายเหตุ
- สถานะ: ลูกค้าใหม่ / ติดต่อแล้ว / ฝากเช่าแล้ว / *(ต้นฉบับขาดหาย — รอยืนยัน)*

ระบบต้องตรวจสอบข้อมูลซ้ำจากเบอร์โทรศัพท์หรือข้อมูลระบุตัวตนที่เหมาะสม และแจ้งเตือนก่อนบันทึกซ้ำ

### 2.2 ฐานข้อมูลทรัพย์สิน (Property Database)

คอนโดแต่ละห้องต้องมีรหัสทรัพย์สินไม่ซ้ำกัน ข้อมูลที่ต้องมี:

- Property ID
- ประเภททรัพย์สิน: Owner / Agent
- ชื่อโครงการ
- อาคารและเลขห้อง
- ที่อยู่และทำเล
- ชั้น
- ขนาดห้อง (ตารางเมตร)
- ประเภทห้อง: Studio / 1 Bedroom / 2 Bedrooms / อื่น ๆ
- จำนวนห้องนอนและห้องน้ำ
- เฟอร์นิเจอร์และเครื่องใช้ไฟฟ้า
- รูปภาพและลิงก์ประกาศ
- ราคาเช่าที่ต้องการ
- ราคาต่ำสุดที่อนุมัติให้เสนอได้
- วันพร้อมเข้าอยู่
- สถานะห้อง: ว่าง / มีนัดดู / อยู่ระหว่างเจรจา / จองแล้ว / ทำสัญญาแล้ว / ไม่ว่าง
- วันหมดสัญญาฝากเช่า (สำหรับ Agent)
- Owner ID ที่เป็นเจ้าของห้อง
- Agent ผู้รับผิดชอบ
- วันที่แก้ไขข้อมูลล่าสุด

**ข้อกำหนดสำคัญ:** ทรัพย์สินหนึ่งห้องต้องมีข้อมูลหลักเพียงชุดเดียว แต่สามารถมี Agent หลายคนช่วยทำงานได้ตามสิทธิ์ที่กำหนด

### 2.3 ฐานข้อมูลผู้เช่า (Tenant / Lead Database)

จัดเก็บลูกค้าที่สนใจเช่าคอนโดทุกคนไว้ในฐานข้อมูลกลาง ข้อมูลที่ต้องมี:

- Lead ID
- ชื่อ-นามสกุล
- เบอร์โทรศัพท์
- LINE ID
- สัญชาติ (ถ้าจำเป็นต่อการให้บริการ)
- งบประมาณค่าเช่าต่อเดือน
- ทำเลหรือโครงการที่ต้องการ
- ประเภทห้องที่ต้องการ
- จำนวนผู้เข้าพัก
- วันที่ต้องการเข้าอยู่
- ระยะเวลาที่ต้องการเช่า
- เงื่อนไขพิเศษ เช่น เลี้ยงสัตว์ได้หรือไม่
- แหล่งที่มาของลูกค้า เช่น Facebook, Website, LINE, Referral
- Agent ผู้รับผิดชอบหลัก
- ผู้ร่วมงานหรือ Agent ที่ช่วยปิดการเช่า
- สถานะลูกค้า
- ประวัติการติดต่อและหมายเหตุ

สถานะลูกค้า: New Lead → Contacted → Qualified → นัดดูห้อง → เจรจา → จอง → ทำสัญญา → ปิดการเช่าสำเร็จ
สถานะเพิ่มเติม: Lost / ยกเลิก / ยังไม่ตัดสินใจ

### 2.4 การทำงานร่วมกันหลายคน (Team Collaboration)

ระบบต้องสามารถ:

- ค้นหาลูกค้าและทรัพย์สินจากฐานข้อมูลกลาง
- มอบหมายลูกค้าให้ Agent คนใดคนหนึ่งเป็นผู้รับผิดชอบหลัก
- ให้ Agent คนอื่นเข้าร่วมช่วยงานได้
- บันทึกว่าใครติดต่อหรือแก้ไขข้อมูลเมื่อใด
- เก็บประวัติการโทร แชต นัดหมาย และผลการติดตาม
- แจ้งเตือนเมื่อมี Agent คนอื่นกำลังดูแลลูกค้ารายเดียวกัน
- ป้องกันการสร้างลูกค้าซ้ำโดยไม่จำเป็น
- มี Audit Log สำหรับตรวจสอบย้อนหลัง
- กำหนดสิทธิ์ไม่ให้ผู้ใช้งานที่ไม่ได้รับอนุญาตเห็นข้อมูลสำคัญ

ต้องมีระบบ **Lead Ownership** เพื่อป้องกันปัญหาการแย่งลูกค้าระหว่าง Agent โดยกำหนดผู้ดูแลหลักและประวัติการโอนลูกค้าอย่างชัดเจน

## 3. Module 2: ระบบปล่อยเช่าและจัดการนัดหมาย

### 3.1 การจับคู่ลูกค้ากับห้องเช่า

ระบบต้องค้นหาห้องที่ตรงกับความต้องการของลูกค้า โดยเลือกเงื่อนไขได้ เช่น:

- ทำเลหรือโครงการ
- งบประมาณ
- ขนาดห้องและประเภทห้อง
- วันที่พร้อมเข้าอยู่
- ระยะเวลาการเช่า
- เงื่อนไขเลี้ยงสัตว์
- สถานะห้องว่าง

แสดงผลห้องที่ตรงเงื่อนไข พร้อมราคา รูปภาพ รายละเอียด และผู้ดูแลห้อง
Agent สามารถบันทึกห้องที่เสนอให้ลูกค้าแต่ละรายได้ เพื่อไม่ให้ข้อมูลกระจัดกระจายอยู่ในแชตส่วนตัว

### 3.2 ระบบนัดดูห้อง (Appointment Management)

ทุกการนัดหมายต้องบันทึกข้อมูลดังนี้:

- Appointment ID
- ลูกค้าที่นัด
- ห้องที่นัดดู
- วันที่และเวลา
- สถานที่นัดพบ
- Agent ผู้พาลูกค้าดูห้อง
- เจ้าของห้องหรือผู้ประสานงาน
- สถานะการนัด
- หมายเหตุ

สถานะนัดหมาย: รอยืนยัน / ยืนยันแล้ว / นัดสำเร็จ / ยกเลิก / ลูกค้าไม่มาตามนัด / เลื่อนนัด

ระบบต้องมีปฏิทินรวมของทีม และตรวจสอบการนัดหมายซ้อนของ Agent คนเดียวกัน
สามารถบันทึกนัดหมายหลายห้องสำหรับลูกค้ารายเดียวกันได้

### 3.3 การติดตามลูกค้า (Follow-up)

หลังจากนัดดูห้อง ระบบต้องให้ Agent บันทึกผล เช่น:

- ลูกค้าชอบห้อง
- ลูกค้าขอต่อรองราคา
- ลูกค้าขอดูห้องอื่น
- ลูกค้ารอพิจารณา
- ลูกค้าไม่สนใจ
- ลูกค้าตกลงเช่า

กำหนดวันติดตามครั้งถัดไป พร้อมแจ้งเตือน Agent และ Manager เมื่อเลยกำหนด

### 3.4 ระบบจองห้อง (Booking)

เมื่อผู้เช่าตกลงเช่า ต้องบันทึก:

- ห้องที่จอง
- ค่าเช่าต่อเดือน
- เงินจอง
- เงินประกัน
- ค่าเช่าล่วงหน้า
- วันที่เริ่มสัญญาและสิ้นสุดสัญญา
- วันที่ชำระเงิน
- ผู้รับเงิน
- สถานะการชำระเงิน
- เอกสารประกอบการจอง

เมื่อจองสำเร็จ ระบบต้องเปลี่ยนสถานะห้องตามกฎที่กำหนด และป้องกันการจองซ้ำในช่วงเวลาเดียวกันโดยไม่แจ้งเตือน

### 3.5 ระบบสัญญาเช่า

จัดเก็บข้อมูลสัญญา:

- เลขที่สัญญา
- ผู้เช่าและเจ้าของห้อง
- ห้องที่เช่า
- ค่าเช่า
- เงินประกันและค่าเช่าล่วงหน้า
- วันเริ่มและวันหมดสัญญา
- ไฟล์สัญญา
- สถานะการลงนาม

มีระบบแจ้งเตือนวันหมดสัญญาล่วงหน้า เช่น 30, 60 และ 90 วัน โดยปรับจำนวนวันได้

### 3.6 การบันทึกประวัติการเช่า

ลูกค้าหนึ่งรายสามารถเช่าหลายห้องในต่างช่วงเวลาได้ และห้องหนึ่งสามารถมีผู้เช่าหลายรายตามลำดับเวลา
ระบบต้องเก็บประวัติการเช่าเดิมไว้ ไม่เขียนทับข้อมูลสัญญาเก่า

## 4. Module 3: ระบบคำนวณรายได้และส่วนแบ่ง Agent

โมดูลนี้เป็นส่วนสำคัญของระบบ ต้องแยกรายได้ Owner และ Agent อย่างชัดเจน

### 4.1 รูปแบบรายได้ของ Owner

กรณีเราเป็นเจ้าของห้องเอง ให้บันทึก:

- ค่าเช่าตามสัญญา
- ค่าเช่าที่รับจริง
- รายรับอื่น ๆ
- ค่านายหน้าที่จ่ายให้ Agent ภายในหรือภายนอก
- ค่าใช้จ่ายที่เกี่ยวข้อง
- รายได้สุทธิจากการปล่อยเช่า

สูตรพื้นฐาน:
รายได้สุทธิ = ค่าเช่าที่รับจริง + รายรับอื่น ๆ − ค่านายหน้า − ค่าใช้จ่ายที่เกี่ยวข้อง
ต้องแยกยอดเงินตามเดือนและตามห้องได้

### 4.2 รูปแบบรายได้ของ Agent

กรณีรับฝากเช่า ให้บันทึก:

- ค่าเช่าต่อเดือน
- อัตราค่านายหน้าตามข้อตกลง
- ระยะเวลาที่ใช้คำนวณค่านายหน้า
- จำนวนเงินค่านายหน้ารวม
- ส่วนแบ่งของ Agent แต่ละคน
- ส่วนแบ่งของบริษัทหรือผู้บริหาร
- วันที่ได้รับเงินจากเจ้าของห้อง
- วันที่จ่ายส่วนแบ่ง Agent
- สถานะการจ่ายเงิน

ระบบต้องรองรับรูปแบบค่านายหน้าที่แตกต่างกัน เช่น:

1. ค่านายหน้าเท่ากับค่าเช่า 1 เดือน
2. ค่านายหน้าคิดเป็นเปอร์เซ็นต์ของค่าเช่ารวม
3. ค่านายหน้าตามจำนวนเดือนที่ระบุในข้อตกลง
4. ค่านายหน้าตามจำนวนเงินที่กำหนด
5. ค่านายหน้าแบบกำหนดเองเป็นรายห้องหรือรายสัญญา

### 4.3 การแบ่งค่านายหน้า

ระบบต้องรองรับการแบ่งค่านายหน้าระหว่าง:

- Agent ผู้หาลูกค้า
- Agent ผู้ดูแลห้อง
- Agent ผู้พาลูกค้าดูห้อง
- Agent ผู้ปิดการเช่า
- บริษัท

กำหนดเปอร์เซ็นต์หรือจำนวนเงินแยกตามบทบาทได้ และต้องสามารถเปลี่ยนสัดส่วนเป็นรายดีลได้โดยผู้มีสิทธิ์

ตัวอย่าง: ค่านายหน้ารวม 30,000 บาท

- Agent A ผู้หาลูกค้า: 30% = 9,000 บาท
- Agent B ผู้ดูแลห้อง: 20% = 6,000 บาท
- Agent C ผู้ปิดการเช่า: 30% = 9,000 บาท
- บริษัท: 20% = 6,000 บาท

รวมส่วนแบ่งทั้งหมด 100% = 30,000 บาท
ระบบต้องตรวจสอบว่าส่วนแบ่งรวมเท่ากับ 100% หรือยอดเงินรวมไม่เกินค่านายหน้าที่ได้รับอนุมัติ หากไม่ตรงต้องแจ้งเตือนก่อนบันทึก

### 4.4 การคำนวณและสถานะการจ่ายเงิน

สถานะค่านายหน้า:

- รอคำนวณ
- รอตรวจสอบ
- อนุมัติแล้ว
- รอรับเงินจากเจ้าของห้อง
- ได้รับเงินแล้ว
- รอจ่าย Agent
- จ่ายแล้ว
- ยกเลิกหรือปรับปรุงรายการ

ระบบต้องเก็บวันที่ จำนวนเงิน ผู้อนุมัติ และหลักฐานการรับหรือจ่ายเงิน
หากมีการแก้ไขค่านายหน้าหลังอนุมัติ ต้องบันทึกประวัติการแก้ไขและผู้ดำเนินการ ห้ามแก้ไขยอดเดิมโดยไม่มีประวัติ

### 4.5 รายงานรายได้

ต้องสามารถออกรายงานตาม:

- รายวัน รายเดือน รายปี
- Owner / Agent
- โครงการและห้อง
- Agent รายบุคคล
- รายการเช่าหรือสัญญา
- ค่านายหน้ารวม
- ส่วนแบ่งแต่ละ Agent
- รายได้บริษัท
- ยอดรับเงินแล้วและยอดค้างรับ
- ยอดจ่ายแล้วและยอดค้างจ่าย

สามารถ Export เป็น Excel หรือ CSV ได้

- จำนวนห้องทั้งหมด
- จำนวนห้องว่าง
- จำนวนห้องที่มีผู้เช่า
- จำนวนห้องที่อยู่ระหว่างจอง
- จำนวนลูกค้าใหม่ในเดือนนี้
- จำนวนการนัดดูห้อง
- จำนวนดีลที่ปิดได้
- อัตราการปิดการเช่า
- รายได้จาก Owner
- ค่านายหน้าจาก Agent
- ส่วนแบ่ง Agent
- รายได้สุทธิของบริษัท
- ยอดค้างรับและค้างจ่าย

สามารถเลือกช่วงเวลาและกรองตามทีม Agent หรือโครงการได้

## 6. ระบบแจ้งเตือน

ระบบต้องแจ้งเตือนเมื่อ:

- มีลูกค้าใหม่เข้าระบบ
- มีการมอบหมายลูกค้าให้ Agent
- ใกล้ถึงเวลานัดดูห้อง
- มีการเลื่อนหรือยกเลิกนัด
- ถึงกำหนดติดตามลูกค้า
- มีการจองห้อง
- ใกล้หมดสัญญาเช่า
- ถึงกำหนดรับหรือจ่ายค่านายหน้า
- มีรายการรออนุมัติ

ช่องทางแจ้งเตือนอาจเป็น Notification ภายในระบบ อีเมล หรือ LINE โดยขึ้นอยู่กับช่องทางที่เลือกเชื่อมต่อ

## 7. ข้อกำหนดด้านความปลอดภัยและการใช้งาน

- รองรับการใช้งานผ่าน Web Browser บนคอมพิวเตอร์และโทรศัพท์มือถือ
- ผู้ใช้งานต้องเข้าสู่ระบบด้วยบัญชีของตนเอง
- กำหนดสิทธิ์ตามบทบาทและข้อมูลที่ได้รับมอบหมาย
- บันทึกประวัติการเพิ่ม แก้ไข ลบ และอนุมัติรายการสำคัญ
- สำรองข้อมูลอย่างสม่ำเสมอ
- ป้องกันข้อมูลส่วนบุคคลของลูกค้ารั่วไหล
- รองรับการค้นหาด้วยชื่อ เบอร์โทรศัพท์ โครงการ และเลขห้อง
- รองรับการ Export รายงานตามสิทธิ์
- มีระบบจัดการไฟล์รูปภาพ เอกสาร และสัญญา
- ต้องมีการยืนยันก่อนลบข้อมูลสำคัญ และควรใช้การเก็บประวัติหรือ Archive แทนการลบถาวร

## 8. ขอบเขตงานที่ต้องส่งมอบ

ผู้พัฒนาต้องส่งมอบ:

1. ระบบฐานข้อมูลกลางสำหรับลูกค้า เจ้าของห้อง และทรัพย์สิน
2. ระบบจัดการลูกค้าและการทำงานร่วมกันหลายคน
3. ระบบนัดดูห้องและติดตามการเช่า
4. ระบบจองและจัดเก็บสัญญา
5. ระบบคำนวณรายได้และแบ่งค่านายหน้า
6. Dashboard และรายงาน
7. ระบบผู้ใช้งานและกำหนดสิทธิ์
8. คู่มือการใช้งาน
9. เอกสารโครงสร้างฐานข้อมูลและ API หากมี
10. ระบบสำรองและกู้คืนข้อมูล
11. การทดสอบระบบก่อนส่งมอบ

## 9. เกณฑ์ตรวจรับงาน (Acceptance Criteria)

ถือว่าระบบผ่านการตรวจรับเมื่อ:

- สามารถแยกห้อง Owner และ Agent ได้ถูกต้อง
- สามารถใช้ฐานข้อมูลลูกค้าร่วมกันโดยไม่สร้างข้อมูลซ้ำโดยไม่จำเป็น
- สามารถระบุผู้รับผิดชอบลูกค้าและดูประวัติการทำงานย้อนหลังได้
- สามารถนัดลูกค้าดูหลายห้องและตรวจสอบนัดหมายซ้อนได้
- สามารถติดตามสถานะลูกค้าจนถึงการทำสัญญา
- สามารถคำนวณค่านายหน้าและแบ่งส่วนแบ่งได้ตรงตามเงื่อนไข
- สามารถตรวจสอบรายรับ รายจ่าย ยอดค้างรับ และยอดค้างจ่ายได้
- ผู้ใช้งานเห็นเฉพาะข้อมูลตามสิทธิ์ที่กำหนด
- รายงานยอดรวมตรงกับรายการธุรกรรมจริง
- ผ่านการทดสอบกรณีใช้งานปกติและกรณีผิดพลาดที่สำคัญ
