# แบบฟอร์มตรวจรับงาน (UAT Checklist) — ระบบ RRS

เอกสารนี้ใช้สำหรับเจ้าของงานและผู้เกี่ยวข้องตรวจรับระบบตามเกณฑ์ตรวจรับงานใน `docs/srs.md` ข้อ 9

## 1. เกณฑ์ตรวจรับหลักตาม SRS ข้อ 9

| รหัส | หัวข้อตรวจรับ | ขั้นตอนทดสอบ | ผลลัพธ์ที่คาดหวัง | สถานะ |
| --- | --- | --- | --- | --- |
| UAT-01 | แยกห้อง Owner และ Agent | สร้างห้องประเภท `OWNER` (ของบริษัท) และ `AGENT` (รับฝากจากเจ้าของ) ในหน้า `/assets` | ระบบแสดงป้ายประเภทถูกต้อง ห้อง `OWNER` ผูกตารางค่าเช่ารายเดือนและข้ามขั้นรอรับเงินเจ้าของในค่านายหน้า | [ ] ผ่าน |
| UAT-02 | ใช้ฐานข้อมูลลูกค้าร่วมกันโดยไม่สร้างซ้ำ | Agent B กรอกเบอร์โทรลูกค้าที่มีอยู่แล้วของ Agent A ในหน้า `/leads` | ระบบเตือนทันทีว่ามีลูกค้ารายนี้แล้ว แสดงชื่อผู้ดูแลแต่ปกปิดข้อมูลติดต่อ และมีปุ่มขอร่วมงาน | [ ] ผ่าน |
| UAT-03 | ระบุผู้รับผิดชอบลูกค้าและดูประวัติย้อนหลัง | เปิดดูรายละเอียด Lead, โอนผู้ดูแลโดย Manager, บันทึก Activity | แสดงผู้รับผิดชอบปัจจุบัน ประวัติการโอน (`lead_assignments`) และ `<Timeline />` ย้อนหลังครบ | [ ] ผ่าน |
| UAT-04 | นัดลูกค้าดูหลายห้องและตรวจนัดซ้อน | สร้างนัดหมายเลือก 2 ห้องพร้อมกัน และลองสร้างนัดซ้อนเวลาของ Agent คนเดิม | บันทึกนัดหลายห้องได้ และแจ้งเตือนนัดซ้อน (`409`) ให้ยืนยันก่อนบันทึก | [ ] ผ่าน |
| UAT-05 | ติดตามสถานะลูกค้าจนถึงการทำสัญญา | บันทึกผลติดตามรายห้อง → สร้างใบจองและรับชำระเงิน → แปลงเป็นสัญญาเช่าและลงนาม | สถานะห้องและสถานะลูกค้าเปลี่ยนอัตโนมัติตามลำดับ (`BOOKED` → `CONTRACTED`) | [ ] ผ่าน |
| UAT-06 | คำนวณค่านายหน้าและแบ่งส่วนแบ่งตามเงื่อนไข | คำนวณค่านายหน้าทั้ง 6 สูตร แบ่งส่วนแบ่ง 30/20/30/20 หักภาษี ณ ที่จ่ายฟรีแลนซ์ 3% | ยอดรวมตรงทุกสตางค์ เศษสตางค์เข้าแถวบริษัท อนุมัติแล้วเก็บ snapshot ใน `commission_revisions` | [ ] ผ่าน |
| UAT-07 | ตรวจสอบรายรับ รายจ่าย ค้างรับ และค้างจ่าย | บันทึกรับค่าเช่าห้อง Owner, บันทึกค่าใช้จ่าย, ดูหน้า `/finance` และ `/commissions` | ตัดยอดงวดค่าเช่าอัตโนมัติ แสดงรายได้สุทธิห้อง Owner และยอดค้างรับ/ค้างจ่ายถูกต้อง | [ ] ผ่าน |
| UAT-08 | ผู้ใช้งานเห็นเฉพาะข้อมูลตามสิทธิ์ (RBAC) | ล็อกอินด้วย Admin, Manager, Agent A, Agent B (คนละทีม), และ Accounting | Agent ไม่เห็น `minRentPrice` ของคนอื่น เห็นเบอร์โทรคนอื่นแบบ mask (`08x-xxx-xxxx`) และเข้า `/settings` ไม่ได้ | [ ] ผ่าน |
| UAT-09 | รายงานยอดรวมตรงกับรายการธุรกรรมจริง | เปรียบเทียบตัวเลขบนหน้า `/` (Dashboard) กับ `/reports` และไฟล์ Export CSV/Excel | ยอดรายได้สุทธิ ค่านายหน้ารวม และค้างรับค้างจ่ายตรงกันทุกตัวกรอง 100% | [ ] ผ่าน |
| UAT-10 | กรณีผิดพลาดสำคัญและการป้องกันข้อมูล | ทดสอบจองห้องซ้ำช่วงวันที่ทับกัน, แบ่งค่านายหน้าไม่ครบ 100%, แก้ค่านายหน้าหลังอนุมัติไม่ใส่เหตุผล | ระบบบล็อกและแสดงข้อความแจ้งเตือนภาษาไทยที่ชัดเจนทุกรายการ | [ ] ผ่าน |

## 2. การตรวจสอบความปลอดภัยและ PDPA

| รหัส | หัวข้อตรวจรับ | ขั้นตอนทดสอบ | ผลลัพธ์ที่คาดหวัง | สถานะ |
| --- | --- | --- | --- | --- |
| UAT-11 | ยืนยันตัวตน 2 ขั้นตอน (2FA) | ล็อกอินด้วยบัญชี Admin หรือ Accounting | บังคับตั้งค่าและยืนยันรหัส TOTP 6 หลักก่อนเข้าใช้งาน | [ ] ผ่าน |
| UAT-12 | Audit Log ห้ามแก้ไขหรือลบ | ตรวจสอบประวัติใน `<Timeline />` และทดสอบแก้ไขตาราง `audit_logs` | บันทึกผู้กระทำ เวลา IP ค่าก่อน-หลังครบ และฐานข้อมูลปฏิเสธการ UPDATE/DELETE | [ ] ผ่าน |
| UAT-13 | สิทธิ์เจ้าของข้อมูลส่วนบุคคล (PDPA DSR) | ส่งออกข้อมูล JSON/PDF และกดลบข้อมูลระบุตัวตน (Anonymize) ในหน้า `/settings` แท็บ PDPA | ค้นหาชื่อ/เบอร์เดิมไม่เจอทั้งในตารางหลักและ `audit_logs` แต่ยอดในรายงานการเงินไม่เปลี่ยน | [ ] ผ่าน |
